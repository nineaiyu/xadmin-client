# UI 深度对比与诊断：4.2 vs 5.0（当前 dev）

> 2026-11-04 立项。背景：用户反馈「当前版本 UI 不如 4.2 好看」。
> 本文是**逐文件源码比对**的产物——两版全部样式与布局源码逐行读过，
> 未采信任何既有审查报告；所有数值均从源码与官方依赖包中直接核对。
> 结论与整改规范见 [ui-refinement-spec.md](ui-refinement-spec.md)，
> 评审用并排预览见 [ui-4.2-vs-5.0-preview.html](ui-4.2-vs-5.0-preview.html)。

## 一、4.2 是哪份代码（版本判定）

### 1.1 候选与判定

`xadmin-client` 仓库中 `name: xadmin`（非上游模板 `vue-pure-admin`）的 4.2 系列 tag 共 5 个：

| tag        | 创建日期       | client package.json  | 备注                           |
| ---------- | -------------- | -------------------- | ------------------------------ |
| v4.2.0     | 2024-11-18     | `"version": "4.1.5"` | 版本字段未随发版 bump          |
| v4.2.1     | 2024-11-22     | `"version": "4.1.5"` |                                |
| v4.2.2     | 2024-12-06     | `"version": "4.1.5"` |                                |
| v4.2.3     | 2025-04-01     | `"version": "4.1.5"` |                                |
| **v4.2.5** | **2025-10-28** | `"version": "4.1.5"` | **4.2 系列最后一版，本文采用** |

**本报告以 `v4.2.5` 为「4.2」的代表**，判定依据：

1. **`v4.2.5` 是 4.2 维护线的最后一版**（此后 4.2 不再发版，5.0.0 于 2026-10-16 发布），
   是用户在升级 5.0 前实际运行时间最长、记忆中最可能的「4.2」形态；
2. `xadmin-server` 同名 tag `v4.2.5` 的 `server/const.py` 为 `VERSION = '4.2.1'`，
   证明这是本项目的自有发版线（版本字段与 tag 名有偏差是 4.2 时代的惯例，
   client 侧 `package.json` 在整个 4.2.x 线都停在 4.1.5）；
3. **4.2.x 线内 UI 无实质漂移**：`git diff v4.2.3 v4.2.5 -- src/style` 仅 4 个文件
   （sidebar.scss 的 `!important` 修复、tailwind.css 前缀迁移等），核心视觉规格
   （菜单项高 50px、激活块 3px 圆角实心主色、灰底表头）自 4.2.0 起未变——
   选哪一版 4.2 不影响结论。

**不确定性说明**：无法向用户确认其「4.2」具体指哪个小版本；由于 4.2.x 线内
UI 稳定（见上），该不确定性对诊断结论无影响。另：`element-plus` 在 4.2 是
`2.11.5`（pnpm-lock 核对），当前是 `2.14.5`；EP 自身默认值随小版本的变化
未逐项展开——影响面小，本项目的显式覆写占主导。

### 1.2 当前版本基准

- 工作区 `dev` 分支 HEAD `61a35b5ed`（2026-11-03），`package.json` = 5.0.2，
  与 `xadmin-server/server/const.py` 的 `VERSION = "5.0.2"` 一致；
- 视觉重构的时间线（`git log` 追踪，全部发生在 5.0 线内）：
  - `9d523e7a6`（2026-10-10）`feat(design): 设计体系令牌化迁移与交互升级`
    ——引入 tokens 三层体系，`platform-config.json` 主色 `#409EFF → #006BE6`；
  - `0b0c6eaa4`（2026-10-14）`feat(ui): 视觉与动效对齐 vben（圆角/语义色/暗色令牌/密度/过渡参数）`
    ——**批量视觉口径切换的关键提交**（EP 圆角 4→8px、行高 1.5→1.15、
    菜单项高 48→42、表头底纹改卡面同底、语义色对齐 vben）；
  - `5488017cf`（2026-11-03）`feat(style): 列表页骨架一张工作纸化与视觉试点落地（卡片贴地/表格分层/看板主角化）`
    ——列表页重排（页头 + 单卡 + hairline），**即用户反馈前一天**，感知上「页面忽然变了」的直接来源。

> 三条提交的动机都是「对齐 vben / 令牌化治理」，属于**有意的风格迁移**，
> 不是无意的样式腐化——这一点决定了整改方案的形态：不是回滚，
> 而是在新令牌体系内校准「被拍平」的层次与密度。

## 三、根因诊断：为什么「现在不如 4.2 好看」

### (a) 客观退化（对比度 / 节奏 / 层次变差，有数值证据）

1. **导航失去唯一的高饱和锚点**。4.2 侧栏的激活项是实心 `#409EFF` 色块+白字，
   是整个左栏唯一的强对比元素；5.0 改为主色 15% 透明底+主色字（浅色皮肤，
   semantic.scss），配合变深的主色，侧栏整体成为「灰白+淡蓝」的低对比面。
   数值：激活块与菜单底的明度差从 ~62% 降至 ~6%；激活文字对比 2.8:1（白字）→
   4.15:1（主色字，仍略低于 AA 4.5:1）。**「一眼知道自己在哪」的导航功能被削弱。**
2. **表头层次坍塌**。底 `#f5f7fa→#fafafa`（与卡面仅差 ~2% 明度）、字
   `#303133→#606266`、字号 `14→12px`。表头从「灰底深字的强结构线」退化为
   「近白底灰字小标题」，对比度 12:1→5.9:1；叠加行距收紧（47→41px）与正文
   14→13px，**表格的「信息栅格」感明显减弱**，这是日常页面（占比最大）观感
   变「素」的主因之一。
3. **全局正文行高 1.5→1.15**（reset.scss html）。1.15 是控件口径（vben 源），
   拿来当正文行高后，所有多行文本（描述列、详情、通知、聊天）视觉上「挤成一团」。
4. **卡片边界近于不可见**。浅色模式卡面与页底仅差 ~5% 明度（两版相同），
   但 4.2 的列表页靠「灰表头带+蓝块」拉层次；5.0 把层次寄托在
   「1px `#ebeef5` 描边 + `0 1px 2px 6%` 贴地阴影」上——这两者在
   `#eef2f7` 页底上肉眼几乎读不出，**「一张工作纸」变成「一整片灰白」**。
5. **微动效口径分裂**（见 (c)），hover 反馈快的快、动的动，缺一个统一节拍。

### (b) 主观风格变化（有意的 vben 化，用户偏好旧风格）

1. **主色 `#409EFF → #006BE6`**：更商务、更沉；客观上修复了白字对比度（2.8→4.9:1），
   但「鲜亮感」下降——这是感知上「颜色不好看了」的直接来源。
2. **全局圆角 4→8px**：控件、弹窗、卡片全变圆。8px 是 vben/Shadcn 系语言，
   与 Element 用户熟悉的中后台观感差异大；且控件 8px 与卡片 8px 同值，
   「外大内小」的同心关系消失。
3. **顶栏投影→细线、页签「浏览器页签」→圆角块、侧栏 hairline→无**：
   一批「隐喻」被抹平，页面从「有骨架感的管理后台」走向「极简面板」。
4. **暗色整体提亮**：从近黑到蓝灰，见仁见智。
5. 语义色（success/warning/danger）从 EP 原生换为 vben 基色（更粉/更浅），
   与 Element 生态习惯不一致。

### (c) 一致性破损（新旧口径混用）

1. **hover 时长三档并存**：菜单 0.15s、按钮 0.1s（appearance.scss）、
   页签项 0.4s（`--duration-slow`，lay-tag 的 `transition: all 0.4s`）——同一屏内
   顶栏、菜单、页签的反馈节拍不一致。
2. **图标缩放只发生在侧栏**：菜单 hover 图标 `scale(1.2)`，顶栏/工具栏图标无缩放。
3. **圆角非同心**：控件 8px 内嵌在 8px 卡片里；徽标胶囊 9px 与热区 32px 圆形
   共存；菜单激活块 8px 与项高 42px 的比例在折叠态（54px 竖排）下不协调。
4. **描边三源**：`--border`（实色五档）与 `--divider`（前景透明度派生）语义并行，
   个别组件混用（需持续用门禁守住）。
5. 表格「默认档」密度由项目覆写、`small/large` 走 EP 原生——三档之间的
   覆写边界处易出现规格跳变。

### 感知机制小结

4.2 的「好看」=**高对比的有限点缀**（一块亮蓝 + 灰表头带 + 深字浅底大间距）；
5.0 把对比预算平摊到了描边、圆角、微阴影等**低可见度细节**上，同时压紧了
行高与字号。结果：单看每个组件都「更精致、更现代」，合在一起却「更平、更素、
更密」。用户在 4.2→5.0 的一夜之间（5488017cf 恰在反馈前一天合入）看到的是
「所有页面的骨架感同时消失」。

## 四、最关键的 5 个退化点（按感知收益排序）

| #   | 退化点           | 4.2                                  | 5.0 当前                                       | 修复收益                               |
| --- | ---------------- | ------------------------------------ | ---------------------------------------------- | -------------------------------------- |
| 1   | 菜单激活块被拍平 | 实心 `#409EFF` + 白字，radius 3      | 主色/15% 底 + 主色字，radius 8                 | 恢复全站唯一强锚点，感知收益最大       |
| 2   | 表头层次坍塌     | `#f5f7fa` 底 + `#303133` 14px/600    | `#fafafa` 底 + `#606266` 12px/600              | 恢复表格「栅格感」（日常页面占比最大） |
| 3   | 全局行高 1.15    | html 1.5                             | html 1.15                                      | 正文呼吸感恢复，多行文本不再挤压       |

## 五、值得保留的 5.0 改进（整改时不要回退）

1. 令牌三层体系与全部门禁（字面量检查）——一致性基础设施；
2. 主色 `#006BE6` 的对比度收益（白字 4.9:1）与色阶 color-mix 派生；
3. `tabular-nums`、表头单行省略、空态/占位对比度收口（a11y）；
4. `prefers-reduced-motion` 降级、`:focus-visible` 焦点环；
5. 内容区 32/24/24 三档留白节奏与 `.app-card` hover 上浮、暗色顶部高光。

## 六、整改方案概览

分三阶段推进（详细规范与推荐值见 [ui-refinement-spec.md](ui-refinement-spec.md)）：

- **阶段 1 令牌级（低风险，全站受益）**：菜单激活块、表头样式、行高、
  表格密度、卡片描边/阴影——5 个样式/工具文件 + 3 个令牌测试更新 + 重录视觉基线；
- **阶段 2 组件级（中风险）**：圆角同心（控件 6/容器 8）、hover 节拍统一、
  页签形态偏好开关——6~10 个组件文件；
- **阶段 3 页面级（高风险，灰度）**：看板/工作台/设置页等逐页校准。
